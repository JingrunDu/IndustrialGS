# 本机 SAM3 批量测试

设备：独占 NVIDIA H20，97871 MiB 显存；PyTorch 2.5.1、CUDA 12.4。
使用现有 SAM3.1 权重，输入分辨率 1008、BF16、TF32、4 个 CPU 线程。

benchmark_batch.py 实现批量图像编码和批量提示词解码，每批依次推理
person、floor、wall、ceiling，并生成与原脚本规则相同的两类 CPU mask。
测试图片从完整 COLMAP 图像列表等间隔选择，事先载入内存。
耗时包括预处理、编码、解码和 CPU mask 后处理，不包括 OSS 读写或 PNG 编码。
模型先预热；每个 batch 连跑 3 次，吞吐取耗时中位数。

| Batch | 图片/秒 | 峰值 tensor 显存 GiB | 峰值 CUDA 预留 GiB |
|---:|---:|---:|---:|
| 1 | 5.16 | 4.99 | 5.30 |
| 2 | 4.63 | 5.43 | 6.03 |
| 4 | 6.38 | 6.32 | 7.38 |
| 8 | 7.89 | 8.11 | 10.17 |
| 16 | 8.90 | 11.68 | 15.63 |
| 32 | 9.49 | 18.82 | 26.55 |
| 64 | 9.84 | 33.09 | 48.40 |
| 128 | 9.93 | 61.65 | 92.11 |

建议生产先使用 batch 32，必要时选择 64。更大的 batch 吞吐收益很小，
显存压力显著增加。本批样本的边界为 batch 167（连续 3 次通过，约 10.02 张/秒，
峰值 tensor 占用 79.05 GiB、CUDA 预留 94.50 GiB）；168 触发 CUDA OOM。
这不是所有图片内容和软件环境的通用上限。完整记录见 benchmark_h20_capacity.json。
CUDA 预留内存包含可复用缓存，不等于 tensor 实际占用；两个峰值都应参考。

批量适配器在 batch 1 与原始 processor 的两种输出逐像素一致。
4 张样本在 batch 4 与逐张执行之间存在少量像素变化：
人物 mask 最大约 0.002%，语义权重图最大约 0.017%；不能承诺完全相同。
此测试不等价于全量数据质量验证或星云 PyTorch 2.8.0 环境验证。

测试只写本地报告，没有覆盖生产图片。后续已将批量适配接入 generate.py，
默认 batch 32。运行中的旧任务仍使用提交时的代码，重新提交才会启用此版本。
